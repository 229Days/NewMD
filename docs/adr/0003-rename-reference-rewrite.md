# ADR-0003: 重命名 / 移动时的引用重写

- **状态**: 已接受 (Accepted)
- **日期**: 2026-10-15
- **关联**: ADR-0001 §2.8（行 146「文件重命名/移动时做引用重写」）、§2.3（引擎边界）、
  §2.5（往返序列化）、§2.6（未决问题 5 —— 本 ADR 就是它的答案）
- **决策性质**: 一项文件操作 + 其跨文档副作用的落地设计

---

## 1. 背景

`PlatformAdapter.renamePath(from, to)` **三端都已经在了**（tauri 走 `rename_path` 命令，Rust 侧
`create_dir_all` 父目录后 `fs::rename`，对文件与目录都成立；browser 明确抛
`PlatformError`），但全仓**没有一个调用方，也没有任何重命名 UI**。所以这一片是两件事：
先把重命名暴露给读者，再在重命名时重写引用。

动手前先把现场探清楚了，三条实测结论改变了做法：

**① 往返序列化器会重新规范化整篇文档。** `markdown.ts` 的 `stringifyOptions` 强制
`rule: "-"` / `bullet: "-"`，而 `inlineLinkReferences` 会把引用式链接改写成内联式。所以
「parse → 改 url → stringify」这条最顺手的路，会在一次改名里把读者**从没碰过**的格式一起改掉 ——
而且被改的可能是一份他当时并没有打开的文档，屏幕上没有任何迹象。

**② 原始 mdast 带字节偏移。** `parse()` 返回的 `link` / `image` / `definition` 节点上
`position.start.offset` / `end.offset` 都在（实测），区间内就是那个目标的原始拼写：

```
{"type":"link","url":"./a.md","raw":"[dot](./a.md)"}
{"type":"image","url":"./assets/x.png","raw":"![img](./assets/x.png \"t\")"}
{"type":"definition","url":"./notes/a.md","raw":"[label]: ./notes/a.md"}
```

**③ 但代码块里也有同形文本。** 一个 `code` 节点的区间是
` ```\n[not a link](./notes/a.md)\n``` `（实测）—— 拿正则扫全文的写法会**改到代码块里**。
这一条把「按节点区间定点替换」从优化变成了必要条件。

还有两条 `url` 字段本身的实测事实，直接决定匹配怎么写：

| 源文里写的            | `url` 是什么 | 说明                             |
| --------------------- | ------------ | -------------------------------- |
| `[pct](./a%20b.md)`   | `./a%20b.md` | 百分号编码**原样保留**           |
| `[esc](./a\(b\).md)`  | `./a(b).md`  | 反斜杠转义**已解码**             |
| `[angle](<./a b.md>)` | `./a b.md`   | 角括号是语法，不在 `url` 里      |
| `[frag](./a.md#sec)`  | `./a.md#sec` | 片段**并进** `url`，不是单独字段 |

所以「拿 `url` 去源文里找」有时找得到、有时找不到，匹配必须容错，而且**找不到时不能猜**。

## 2. 决定

### 2.1 范围：两个方向，所有相对链接

把 `notes/a.md` 移到 `notes/sub/a.md` 时，两侧都要改：

- **出向**：被移动文档**自己写出去**的相对链接。它换了目录深度，`./assets/x.png` 从
  `notes/assets/` 解到了 `notes/sub/assets/`，全断。
- **入向**：工作区里**指向它**的相对链接。`index.md` 里的 `[a](./notes/a.md)` 必须变成
  `./notes/sub/a.md`。

两个方向用的是同一套算术，分别跑一遍而已。覆盖 `link`、`image`、`definition` **三种节点**，
不是只覆盖图片：`[另一篇](./notes/a.md)` 这种跨文件链接和图片一样日常，只看图片等于
ADR-0001 §2.8「不产生断链」那句承诺只兑现了一半。**代价只在扫描范围，不在链接种类。**

这也是 ADR-0001 §6 未决问题 5 的答案。

### 2.2 一次操作就是「把一个路径换成另一个路径」

引擎按 `(from, to)` 两个绝对路径写，**不区分「改名」和「移动」**，也不看两者是不是同一个目录。
文件夹改名就是「整棵子树换位置」，同一套算术，不变量是：

> 子树**内部**之间的引用不变，只有**跨子树边界**的引用才改。

UI 这一片只暴露**原地改名**；「移动到另一个文件夹」留给以后，届时引擎不用动。

### 2.3 入口：侧栏文件树的行内改名

文件树每一行（文件与文件夹都算）可以进入改名态：标签变成一个输入框，回车确认、Esc 取消。
不做右键菜单组件，也不做拖拽移动。

- 树要新增「当前选中行」的概念 —— 今天点一下就打开文件，没有选中态。
- 树的 `entries` 按**绝对目录路径**做 key、`expanded` 也是一串绝对目录路径，而 `refresh()`
  只重列**已经作为 key 存在的目录**、不重走 `rootPath`。所以目录改名之后 `refresh()` 不够，
  必须把 key 与 `expanded` 一起搬迁。
- 同名已存在 → **拒绝并提示**，不覆盖。注意大小写不敏感的文件系统上，`a.md` → `A.md` 时
  那个「已存在」就是它自己，不能判成冲突。

### 2.4 重写是定点拼接，不是往返

拿到 `parse()` 的原始树（**不是** `parseTransformed()`：引用式链接在那一棵树里已经被
`inlineLinkReferences` 展平成内联式，看不到作者实际写的 `[label]: url`），对每个
`link` / `image` / `definition`：

1. 读出 `url`，按 §2.5 判断该不该改；不改就跳过；
2. 算出新目标，按 §2.6 拼出新的相对写法；
3. **只在该节点的 `[start.offset, end.offset)` 区间内**把旧目标文本换成新的。

第 3 步是这一节的全部要点：区间之外的字节**一个都不动**，所以代码块、围栏、缩进、
项目符号、引用式链接的拼法全部原样保留。一份没有被改到的文档，重写结果与原文**逐字节相同**
（这条要有一条测试钉住）。

### 2.5 哪些目标算是「要改的相对路径」

| 形态                         | 改吗 | 理由                                                   |
| ---------------------------- | ---- | ------------------------------------------------------ |
| `./a.md`、`../x/a.png`       | ✅   | 这就是引用重写本身                                     |
| `a.md`（无 `./` 前缀）       | ✅   | 同为相对路径；重写后**统一写成 `./a.md`**              |
| `./a.md#sec`、`./a.md?x=1`   | ✅   | 路径部分换掉，`#…` / `?…` 后缀原样跟在后面             |
| `/etc/a.md`、`C:\a.md`       | ❌   | 绝对路径，与文档在哪无关                               |
| `https:`、`mailto:`、`data:` | ❌   | 带 scheme；判据是「冒号出现在第一个 `/` 之前」         |
| `#sec`                       | ❌   | 同文档内的片段                                         |
| 空串                         | ❌   | 无目标                                                 |
| `![](x)` 里的 `x` 不存在     | ✅   | **按算术改，不按存在性**：目标可能还没建，也可能刚被删 |

裸 HTML（`<img src="./a.png">`）**不改** —— 那要一个 HTML 解析器，而且本项目文档化的图片写法
就是 `![]()`（见 §3）。

### 2.6 新路径怎么写

与 `paste-image.ts` 已经定死的规矩**逐字一致**：`./` 开头、正斜杠、相对**引用所在文档**的目录
（那一条的注释写明了理由：Windows 上编辑、Linux 上读的文档也要解得开）。

新增纯函数 `pathRelative(from, to): string` 到 `core/src/platform/path.ts`，由 barrel 导出。
**不做成适配器方法**：它是纯算术，不需要宿主语义，而适配器每加一个方法就要同步 browser + tauri

- 7 个 fake 适配器（ADR-0001 §2.3、HANDOFF §2 约束 6）。同目录时要产出 `./a.md` 而不是 `a.md`。

### 2.7 匹配容错：找不到就跳过，不猜

`url` 是解码过的（§1 表），源文里却可能写着转义或角括号。所以：

1. 先按 `url` 原样在节点区间里找；
2. 找不到就试它的几种合法拼法（转义还原、角括号包裹、百分号编码与否）；
3. **都不中就跳过这一处**，并在结果里计入「未重写」的条数，由调用方提示读者。

宁可漏一处并说出来，也不要在读者没看的文档里改错一个字节。

### 2.8 已打开文档：改内存，标签变脏

| 文档状态       | 怎么改                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| 已打开（标签） | 改内存里的 `content`，**不动** `savedContent` → 标签变脏，读者看得见脏点，下次保存 / 自动保存按新路径落盘 |
| 没打开（磁盘） | 读 → 改 → 写                                                                                              |

**顺序是硬要求：先补标签的 `path` / `fileName`，再做磁盘改名。** 自动保存走 `persistDoc`，它直接
拿标签的 `path` 去 `writeTextFile`，而 Rust 的 `write_text_file` 会先 `create_dir_all` 父目录 ——
所以只要标签还指着旧路径，800ms 之后的那一拍就会**把旧文件原地写回来**，改名等于没发生。
这条要有一条测试钉住（拿假适配器断言写入的目标路径）。

改成内存还有一个直接后果：被改名那个标签的**撤销历史会被清掉**（`EditorPane` 按
`(path, fileName)` 判断「换文档了」，于是重推 `setContent`）。接受，并写进 §3。

### 2.9 扫描范围：整个工作区 + 所有已打开的标签

递归读工作区下所有文件（跳过 `node_modules` / `.git` / 隐藏目录），再加上所有已打开的标签
（含工作区之外的）。**只扫已打开的文档是不够的** —— 「`index.md` 引用了一篇我没打开的笔记」
正是断链最常见的形状。

代价诚实记在 §3：个人库几百到几千个文件，Tauri IPC 上大约 1–3 秒，期间要有忙碌提示。

### 2.10 平台与文案

- **桌面端不需要新命令**：`rename_path` 已经建父目录，且对文件与目录都成立。
- **浏览器适配器的 `renamePath` 直接抛错**（File System Access API 不支持）。入口照常显示，
  抛出的错误走既有的错误上报 —— 不为一个开发模式加一套能力探测。
- 新增的动作名、输入框的校验提示、重写条数的 toast，**全部双 locale**（HANDOFF §2 约束 4）。
- **无新语法 → 无 golden 语料**：这一片不碰序列化器，也不引入新的 Markdown 写法（§2 约束 2 的分界）。

## 3. 代价与已知缺口

- **被改名标签的撤销历史会被清掉**（§2.8）。等 WYSIWYG 多光标那一片（HANDOFF §4 的 ②）
  做完、标签有了稳定身份之后可以回头修；现在 `sameTab` 就是按 `(path, fileName)` 认人的。
- **跨卷移动会失败**：Windows 上 `fs::rename` 换盘符会报错。**不降级成「复制 + 删」** ——
  那是一个会在大文件上假装成功的操作，报错更诚实。
- **裸 HTML 里的相对路径不改**（§2.5）。整个 ADR-0001 方言都不解析 HTML，这里不为它破例。
- **大工作区扫描要 1–3 秒**（§2.9）。可接受，但要给忙碌提示。
- **文档若同时被别的工具打开着**，本应用看不到，重写会与对方的写入互相覆盖。这是「打开的文件
  不重读」（HANDOFF §8）同一类问题的另一面，不在这一片解决。
- **大小写只有变化的改名**（`a.md` → `A.md`）：Windows 上 `fs::rename` 走 `MoveFileEx`，
  理论上可行，但**本片没有实测**。第一天就该拿一条测试把它钉住。
- **不动 `.git`**：重写会改工作区里的文件，读者若开着版本控制，一次改名会显示成一批修改。
  这是应有的行为（引用确实变了），但值得说一句。

## 4. 被否决的方案

| 方案                                           | 否决理由                                                                              |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| 走 `roundTrip()`（parse → 改 url → stringify） | 会把读者没碰过的格式一起改掉（`rule`/`bullet` 强制 `-`、引用式链接改内联式）；见 §1 ① |
| 正则扫全文替换 `](./旧路径)`                   | 会改到代码块与行内代码里的同形文本，实测成立；见 §1 ③                                 |
| 只覆盖图片引用                                 | 跨文件 `.md` 链接继续断，而那正是 ADR-0001 §2.8 承诺的一半；见 §2.1                   |
| 只改磁盘，打开的标签重载                       | 冲掉未保存的改动，并清掉撤销栈；见 §2.8                                               |
| 有脏文档就先逼读者保存                         | 在改名这件小事上挡一道，而内存改写本来就能让改动一个字都不丢；见 §2.8                 |
| 只扫已打开的文档                               | 漏掉最常见的断链形状；见 §2.9                                                         |
| 把 `pathRelative` 做成适配器方法               | 纯算术不需要宿主语义，却要同步 browser + tauri + 7 个 fake；见 §2.6                   |
| 拖拽移动 / 「移动到…」对话框                   | 留给以后：引擎按 `(from, to)` 写，接上不用重写；见 §2.2                               |
| 同名已存在时自动加 `-1` 后缀                   | 静默改掉读者打的名字；拒绝并提示，让他自己决定；见 §2.3                               |

## 5. 未决问题

1. **取消 / 反悔** —— 一次改名会改多个文档，目前整体不可撤销。要不要做「撤销这次重命名」，
   把磁盘改名与所有重写一起回滚？
2. **裸 HTML 里的相对路径** —— 见 §3，等有真实需求再说。
3. **工作区之外的引用** —— 只扫工作区 + 已打开的标签。工作区外的文件引用它时不会被改。
4. **「移动到…」** —— 引擎已经支持，缺的是入口（对话框或拖拽）。见 §2.2。
5. **重命名后的历史** —— 撤销栈被清（§3）。是否需要稳定的标签身份，取决于 v1.0 缺口 ② 的结论。
